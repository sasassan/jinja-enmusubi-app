# 商用化に向けた改善計画

このブランチは本番 main に直接影響を与えない検証用です。各項目は未検証の改善候補であり、不具合確定を意味しません。

## P0 公開前に必須
- [ ] npm ci / npm run lint / npm run typecheck / npm run build をCIで実行する
- [ ] Supabaseの全公開テーブルについてRLSポリシーを確認し、他人のデータへのアクセスを禁止する
- [ ] 認証: 登録、ログイン、ログアウト、パスワード再設定、期限切れセッション、複数端末
- [ ] お気に入り: 未ログイン、ログイン後同期、ログアウト後のデータ分離
- [ ] 画面ごとに loading / empty / error / retry を実装し、DB障害を0件と誤認させない
- [ ] 神社詳細への直接アクセス、存在しないslug、戻る操作の検証
- [ ] APIキー・環境変数・ログへの個人情報露出を点検する
- [ ] 利用規約・プライバシーポリシー・お問い合わせ・退会/データ削除手順を整備
- [ ] 本番データのバックアップと復元手順を文書化
- [ ] PWA更新時の古いキャッシュ、オフライン時のエラー、インストール可否を実機確認
- [ ] 地図の出典表記、地図タイルの利用規約、アクセス上限を確認

## P1 β公開までに優先
- [ ] 神社一覧の全件取得を避け、地図範囲/地域/検索条件でサーバー側ページング
- [ ] 緯度経度がない神社も一覧・検索には表示する
- [ ] 神社データの出典・確認日・修正申請導線を用意
- [ ] 祭神・御利益・由緒の表記ゆれと情報精度をレビュー
- [ ] 地図の大量マーカー描画を性能計測し、必要に応じてクラスタリング/範囲検索
- [ ] 検索入力のデバウンス、検索結果件数、0件時の代替提案
- [ ] スマホのSafe Area、文字サイズ拡大、タップ領域、キーボード操作、スクリーンリーダー
- [ ] Lighthouse/Web Vitalsの測定と低速回線での初期表示改善
- [ ] エラー監視・障害通知・デプロイ後のスモークテスト
- [ ] 画像の著作権、利用許諾、クレジットを確認
- [ ] iOS/Android Capacitorビルドとストア審査要件を確認

## P2 商用成長
- [ ] 地域別検索需要、初回検索完了率、詳細閲覧率、再訪率を匿名集計
- [ ] データ登録・更新・重複統合の管理画面と監査ログ
- [ ] 不正投稿・虚偽情報・権利侵害への通報/対応フロー
- [ ] 広告/課金/事業者向けサービスの仮説と小規模ユーザーテスト
- [ ] 収益モデルに応じた決済・返金・表示義務の検討
- [ ] 多言語対応と訪日観光客向け導線の需要検証
- [ ] データベースインデックス・コスト監視・レート制限
- [ ] バックアップ復元訓練、依存パッケージ脆弱性スキャン

## 受入条件
- 本番 main は承認まで変更しない
- 変更ごとに差分、テスト結果、残存リスクを報告
- 手動テストだけでなく主要導線の自動テストを追加
- データ破壊を伴うマイグレーションは実施しない
- Verdentで検証してからPR作成・本番反映を判断
